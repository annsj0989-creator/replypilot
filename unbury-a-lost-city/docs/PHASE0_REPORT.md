## 1. 실제로 구현한 기능과 작업한 파일

### 발굴 방식 선택 (16장 작업 2·3)
세 가지 방식을 비교했습니다. 상세 표와 근거: [`DIG_SYSTEM_DESIGN.md`](DIG_SYSTEM_DESIGN.md)

| 방식 | 판단 |
|---|---|
| **A. 서버 높이맵 + Terrain 복셀 쓰기** | **채택.** 매끄러운 모래 표면·구덩이 충돌·멀티 복제를 엔진이 처리. 화면의 지형은 높이맵에서만 만들어지므로 진행 상황과 시각 상태가 구조적으로 일치 |
| B. Part 기둥 격자 | 구현은 쉽지만 계단식 블록 외형, 구역당 수백~천여 개 Part |
| C. EditableMesh 변형 메시 | 외형 자유도는 최고지만 변경마다 충돌 재생성·복제 없음·메모리 예산 위험. PHASE 2에서 시각 전용 레이어로 재검토 |

**테스트가 실제로 결함을 잡는지 확인(변이 테스트):** 다음 결함을 일부러 넣었을 때 모두 테스트가 실패했습니다 — ① 복셀 영역 2스터드 어긋남 ② 속도 제한 제거 ③ 구역 경계 검사 제거.

**통합 테스트 내용** — 실제 서버 모듈(`DigService`, `ArtifactService`, `TerrainRenderer`)을 Lune의 Roblox 데이터 타입으로 실행하고, 엔진이 필요한 부분(Terrain, 캐릭터, 시계)만 대체했습니다.
- 정상 스윙 → 높이맵 변경 + `WriteVoxels` 1회, 영역이 4스터드 격자에 맞고 배열 크기가 영역과 일치, Air ↔ 점유율 0 일치
- 거절: 문자열·nil·숫자·테이블·NaN·무한대 / 다른 사람 구역 / 하늘 / 40스터드 밖 / 삽 없음 / 사망 / 내 구역 경계 2스터드 밖
- 같은 순간 10회 요청 → 3회만 처리(버스트), 쿨다운 후 1회 추가
- 유물: 상태가 정확히 `Hidden > Glimpsed > Discovered` 순서, 진행도는 되돌아가지 않고 1.0 도달, 발견 시 주변 모래가 유물 바닥까지 내려가고 받침대 밑 모래는 유지(유물이 뜨지 않음), 발견 기록이 저장용으로 남음

**페이싱 시뮬레이션**(`lune run tests/simulate`, 25회 반복, 쿨다운마다 스윙·이동 시간 제외):

| 도구 | 첫 반짝임 | 발견까지 |
|---|---|---|
| Lv1 기본 삽 (반경 5, 0.30초) | 4회 · 1.2초 | 32회 · **9.6초** (31~34회) |
| Lv2 확장 삽 (반경 7.5, 0.25초) | 3회 · 0.8초 | 13회 · **3.2초** (13~14회) |

→ Lv2가 약 3배 빠름: 사양서의 "2단계 도구는 확실히 우수"를 수치로 충족. 실제 사람은 이동·조준 시간이 더해지므로 첫 발견은 15~25초 정도로 예상되며, 플레이 테스트로 확정해야 합니다.

실제 화면·조작감, 모래가 "만족스럽게" 파이는지, FPS·메모리, 모바일 기기/에뮬레이터, 2인 이상 멀티 클라이언트, 사운드 재생, 애니메이션·삽 쥐는 모양. → 아래 7장의 체크리스트로 확인을 요청드립니다.

| 최악: 깊은 구덩이 1회 스윙이 69칸을 무너뜨림 | 약 116 µs |
| 구역 전체 다시 쓰기(초기화 때만) | 약 350 µs |

→ 6명이 동시에 Lv2로 쉬지 않고 파도(초당 24스윙) 게임 로직은 초당 약 1.5ms. 서버 한 프레임(16.7ms)과 비교해도 매우 작습니다.

**구조상 보장되는 것:** 물리 Part 0개(파편은 모두 입자), 스윙당 RemoteEvent 1회(초당 최대 3.3~4회, Vector3 하나), 스윙당 바뀐 영역만 지형 쓰기, 맵 전체 Part 약 200개.

**측정하지 못한 것:** 엔진의 `WriteVoxels`·지형 메싱·복제 비용, 실제 FPS·메모리, 모바일. Studio에서 **F3**을 누르면 FPS·클라이언트 메모리·서버 발굴 평균/최대 ms·2초당 처리/거절 수가 표시되도록 준비해 두었습니다. 목표: PC 60FPS, 기준 모바일 30FPS 이상.

## 7. 다음 단계의 권장 작업

**PHASE 1로 넘어가기 전에, 사양서 원칙("문제를 발견하면 새 기능보다 기존 문제부터")에 따라 Studio 확인을 먼저 권장합니다.** 약 15분이면 됩니다.

### Studio 확인 체크리스트
1. `build/UnburyALostCity_Phase0.rbxl` 열기 → **Play**. 발굴지 앞에서 시작, 시작 문구와 "여기를 파세요" 마커가 보이는가?
2. 마커 아래에서 마우스를 누르고 있기 → 조준 링·먼지·파편·소리·스윙이 나오고 **모래가 조금씩 내려가는가?** 4스터드 해상도가 거칠어 보이지 않는가?
3. 계속 파기 → 깔때기 구덩이, 깊은 곳의 진한 지층, **걸어서 들어가고 나올 수 있는가?**
4. 약 4번째 스윙에 반짝임·알림·진행 바, 약 30번째 스윙에 발견 연출이 나오는가?
5. **F2**(Lv2) → 링이 커지고 확실히 빨라지는가? **F4**로 초기화 후 반복.
6. **F3** → FPS와 "server dig avg/max ms" 기록.
7. Device 에뮬레이터(휴대폰·태블릿): 파기 버튼이 점프 버튼과 겹치지 않는가? 조이스틱과 파기를 동시에 누를 수 있는가? 모래를 탭하면 그 위치로 조준되는가? 화면을 드래그하면 카메라만 돌고 파지 않는가?
8. Test → Clients and Servers(플레이어 2명): 각자 다른 구역을 받는가? 남의 구역은 빨간 링으로 표시되고 파지지 않는가? 서로의 구덩이가 보이는가?
9. 삽 쥐는 모양, 스윙 애니메이션 상태 확인.

결과(특히 2·3·6·7번)를 알려주시면, 발견된 문제부터 수정한 뒤 PHASE 1 계획을 제안드리겠습니다.
